# v0.9.6 Intelligent Discovery Ecosystem Foundation + Web Beta Release Candidate Report

日期：2026-08-04  
结论：**Web Beta 候选的领域、接口和治理基础已完成；尚未自动获得对外发布批准。**

## 1. 已完成能力

- Discovery Feed 具备统一内容卡片数据：标题、摘要、类型、来源数、重要度、新鲜度、可信分、推荐原因和探索范围。
- WorldEventLifecycle 支持事件状态演进、来源变化、新证据和历史版本链接。
- Personal Discovery 保持兴趣、关注、收藏/反馈的隐私边界：兴趣可由用户控制，世界发现与个人发现分离。
- ContentQualityAssessment、DiscoveryRelation、ContentFreshness 让内容质量、限制、探索关系和更新线索可追溯。
- Developer Connection 已通过 Communication Intelligence 路由产品反馈、Bug、安全报告、案例贡献与合作请求；安全报告为 P0。
- 生态 Port、默认关闭 Feature Flag、PermissionBoundary 和 Web Beta Release Checklist 已建立。

## 2. 架构变化与生态接口

新增 `ecosystem.py`，定义 Community、Expert、Contribution、Notification、AI Provider、Enterprise、Billing 的可替换 Port。`EcosystemExtensionRegistry` 将“注册”与“启用”分开；默认禁用，启用需人工批准。社区、专家、企业、计费、移动端和模型 Provider 目前没有生产实现。

## 3. Web Beta 体验与数据边界

Web Beta 可基于现有领域数据实现世界发现、深度探索、兴趣关注、反馈交流和贡献建议，但本轮未实现 Web UI。系统不采集私人搜索、私人正文、私人聊天或未授权行为；个人化仅使用用户明确确认的兴趣信号。推荐必须有原因、证据和限制。自动系统只能提出 Signal、Candidate、Proposal。

## 4. 安全设计

数据导出、删除、审计、同意、备份恢复和发布人工批准仍由既有 Trust/Beta Operations 机制提供。发布检查要求功能、安全、隐私、版权、备份、恢复、权限、治理和体验全部通过并由人批准。生态接口不可直接修改知识、权限、信誉或规则。

## 5. 测试结果

Ruff 与编译检查通过；`pytest -q`：**54 passed**。新增覆盖 Discovery Feed、内容质量限制、World Event Lifecycle、Discovery Graph 证据要求、Extension Registry 默认关闭和人工启用、权限边界、Developer Connection、Feature Flag、Web Beta 发布门禁。存在 1 条 FastAPI/Starlette 上游 TestClient 弃用警告，不影响本轮结果。

## 6. 发布风险

- 没有 Web UI、生产认证、真实数据迁移、生产备份/恢复演练或受邀用户验证，不能宣称已可公开发布。
- 世界信息连接器、实际 Feed、推荐、通知、社区和 AI Provider 都尚未实现；不能被产品文案描述为已开放。
- 案例和世界事件仍需逐条来源、许可证、证据与人工审核。

## 7. 下一阶段路线

v0.9.7 建议只建设受控 Web Beta：身份认证与授权、静态/人工审核 Feed 页面、数据控制页面、受邀 Beta 协议、受控反馈中心、真实恢复演练和发布审批记录。v1.0 前再评估单一公开来源 Connector、通知适配器与小规模社区协作，始终保持人工治理。
