# v0.9.x Beta Release Candidate 准备报告

日期：2026-08-03  
状态：**工程 RC 准备基线完成；Private Beta 发布仍需人工批准。**

## 1. 项目状态与已实现能力

项目具备发现、来源、证据、案例、知识图谱、搜索、分类、治理、身份基础、监控、响应、受控进化、案例候选展示与 Beta 反馈。v0.9.2 新增 RC 发布状态机、发布证据/风险/回滚模型、Trust Checklist、数据保护中心应用服务、备份恢复演练、Beta 协议/同意/退出模型、运营风险分级、演进日历、指标模型，以及独立沟通智能基础层。

## 2. 安全检查与用户保护

RC 的批准转换要求完整 Trust Checklist 和人工 ReleaseApproval；状态不能跳跃，也没有自动部署。数据保护中心提供按所有者查看、导出、删除和审计记录的可替换存储契约。所有操作均要求执行者与原因；这不是生产认证授权，HTTP 公开入口在真实身份体系就绪前不会开放。

沟通记录默认私有，状态变迁有历史。沟通风险评估只能使用元数据，禁止读取/保存私人正文。AI 交互解释要求列出信息、来源、假设与不确定性。候选案例仍与 Verified Case 严格分离；发布案例需要来源、许可证、证据和人工审核全部通过。

## 3. 备份恢复与稳定性

备份演练创建副本、以 SHA-256 验证完整性、仅破坏隔离恢复副本、从备份恢复并比较哈希。原数据文件不会被修改。事件按 Level 0–3 进入周期观察、治理队列、人工批准或重大事件响应；改进仍须遵循 Issue → Analysis → Proposal → Experiment → Human Approval → Release。

## 4. 测试结果

已执行 Ruff、compileall 和完整 pytest 套件：Ruff 与编译检查通过，`36 passed`。新增测试覆盖 RC 顺序审批、信任门禁、数据导出/删除/审计、非破坏性备份恢复、Beta 协议/同意/退出、案例审核门槛、沟通生命周期、私有保护、反馈结案、受控求助/贡献与 AI 不确定性说明。存在 1 条 FastAPI/Starlette 上游 TestClient 弃用警告，不影响本轮结果。

## 5. 已知风险与 Beta 限制

- 本地 SQLite 适配器不等同生产加密、备份保留、并发或高可用方案。
- 当前没有生产身份认证；因此数据保护操作仅提供应用层契约，不能作为互联网公开接口发布。
- 案例种子仍需逐条来源、许可证和证据复核。
- ReleaseEvidence、RiskAssessment、RollbackPlan 等是领域记录，本轮未接入生产部署平台。
- 沟通模块不提供开放社区、私信平台、自动审核、自动处罚或自动知识修改。

## 6. 下一阶段路线

在进入受邀 Private Beta 前，需完成：认证与授权威胁建模、受控邀请与 BetaAgreement 持久化、生产加密和密钥方案、真实数据迁移/备份恢复演练、逐案审核、隐私政策与安全报告渠道、人工 ReleaseApproval 会议记录。完成后由架构负责人审核 ReleaseEvidence、RiskAssessment、RollbackPlan 和 Trust Checklist，决定是否批准 Private Beta。
