# Intelligent Discovery（智能发现）项目总览

> **帮助用户发现信息、学习经验、理解趋势、辅助决策的 AI 知识发现生态。**

**当前版本**：v0.3.0（Knowledge + Case Intelligence Foundation）

**当前阶段**：Discovery Core + 可信研究 + 案例知识资产基础
**工程状态**：本地 Git `main` 已建立；质量门禁通过。

---

## 1. 项目要解决什么问题

信息并不等于理解，模型回答也不等于可靠决策。智能发现的作用是把一个用户问题，转化为一条可回溯、可审查、可积累的知识发现路径：

```text
用户问题
  → 研究资料与证据
  → 发现、风险、建议与未知项
  → 可读报告与可复用知识
  → 用户基于证据作出判断
```

系统不替用户决定；它必须展示来源、置信度、局限与待确认问题，帮助用户看到更多可能、理解别人经验、降低信息遗漏和判断错误。

## 2. 当前已实现能力（v0.1）

### 发现闭环

| 能力 | 当前行为 |
| --- | --- |
| 创建发现任务 | 接收问题和背景，任务进入研究状态。 |
| 登记资料来源 | 保存标题、URL、摘录、可信度与采集时间。 |
| 来源智能 | 记录来源类型、可信等级、可访问状态和许可证。 |
| 独立证据 | 对资料内具体摘录、定位、关系、验证状态和限制建模。 |
| 形成发现 | 保存关键发现、风险、建议或未知问题。 |
| 证据约束 | 除未知项外，每条结论必须关联本任务的至少一个资料来源。 |
| 状态管理 | `draft → researching → analyzed → completed`，防止跳过关键步骤。 |
| 知识沉淀 | 已完成任务生成可查询知识记录。 |
| 报告生成 | 输出包含背景、资料、发现、风险、建议、未知项和下一步的 Markdown 报告。 |
| 人工复核 | 对具体发现记录接受、拒绝或要求修订的反馈。 |
| 案例智能 | 以来源、证据、验证、版本和生命周期管理案例知识资产。 |
| HTTP 服务 | 提供 FastAPI 接口和交互式 API 文档。 |

### 当前边界

v0.1 **不包含**自动联网研究、自动决策、用户账号、社区、推荐或企业生产能力。资料可以由用户或未来合规研究提供器提供；系统不会把尚未接入的能力伪装成已实现功能。

v0.2 仍**不包含**真实联网研究或模型自动验证；本阶段只完成它们安全接入所需的数据模型、契约和失败语义。

v0.3 仍**不包含**自动案例发现、自动案例分析、社区贡献或推荐；只实现案例资产的可信保存、跟踪和复用基础。

## 3. 总体生态与模块规划

系统先定义生态边界，再逐阶段让模块入住。所有未来模块通过明确能力契约接入，不直接耦合进发现核心。

| 模块 | 目的 | 状态 |
| --- | --- | --- |
| Discovery Core | 创建与协调证据驱动的发现任务 | 已实现（v0.1） |
| Research Engine | 从合规外部来源收集、去重、核验资料 | 契约与失败语义已实现；执行器预留 |
| Opportunity Radar | 发现外部变化与潜在机会信号 | 预留 |
| Decision Analysis | 对选择、风险和约束进行可解释评估 | 预留 |
| Personal Intelligence | 基于明确同意的个人上下文进行发现 | 预留 |
| Recommendation | 给出可解释、可关闭、可反馈的推荐 | 预留 |
| Case Intelligence | 从结构化案例中提炼经验与适用边界 | 案例资产、版本、验证和跨任务关联已实现（v0.3） |
| Community System | 支持分享、审核、协作与举报 | 预留 |
| Contribution System | 认可已验证贡献，支持申诉与审计 | 预留 |
| Enterprise Services | 支持组织工作流、权限、审计与租户隔离 | 预留 |
| Experimental Extensions | 用于未来未知想法的实验性安全插槽 | 长期预留 |

## 4. 长期架构

### 分层与依赖方向

```text
HTTP API / 未来 Web、CLI、桌面端
                 ↓
           Application Services
                 ↓
              Core Domain
                 ↓
           Ports（稳定协议）
                 ↑
SQLite / 未来数据库 / 搜索提供器 / 外部插件
```

### 核心原则

1. **领域优先**：任务、证据、发现和知识模型不依赖 HTTP、数据库或模型 SDK。
2. **端口隔离**：应用服务只依赖抽象协议；SQLite 只是当前可替换实现。
3. **证据优先**：结论必须可回溯；未知项必须显式保留。
4. **插件式演进**：新能力以契约和注册表接入，失败不得破坏发现核心。
5. **兼容性优先**：公开接口默认保持向后兼容；破坏性变更必须有 ADR、迁移方案与主版本升级。
6. **人始终在环**：特别是推荐、评分、机会与决策模块，必须支持解释、反馈、关闭和人工复核。

### 现有核心对象

| 对象 | 责任 |
| --- | --- |
| `DiscoveryTask` | 用户问题、背景与生命周期状态。 |
| `Source` | 可追溯资料来源、摘录与可信度。 |
| `Finding` | 发现、风险、建议或未知项，以及证据与置信度。 |
| `KnowledgeRecord` | 从完成任务沉淀的可复用知识。 |
| `CaseRecord` / `CaseRevision` | 具来源、证据、验证、生命周期和历史的案例知识资产。 |
| `DiscoveryRepository` | 持久化端口，隔离服务与数据库。 |
| `ExtensionRegistry` | 管理未来生态能力的注册边界。 |

## 6. 开发路线

### v0.1：Evidence-led Discovery Core（完成）

验证从问题到可追溯报告的最小闭环。已完成任务编排、资料、发现、知识、报告、HTTP API、SQLite 和回归测试。

### v0.2：Research Intelligence Foundation（完成）

完成来源智能、独立证据、引用、人工复核和研究失败契约。真实外部提供器、来源去重与工作空间仍为后续工作。

### v0.3：Knowledge + Case Intelligence Foundation（完成）

完成可追溯案例资产、严格生命周期、版本历史、跨任务案例引用与报告关联。全局检索、案例索引与可解释选项比较仍为后续工作。

### v1.0：Governed Ecosystem

在安全、隐私、治理与兼容性成熟后，逐步开放机会雷达、个人智能、推荐、社区、贡献、企业服务和第三方扩展。

## 8. 当前验证结果与风险

### 工程验证

| 检查项 | 结果 |
| --- | --- |
| 静态检查 | 通过：`ruff check .` |
| 单元/API/扩展测试 | 通过：11 passed |
| Python 编译检查 | 通过 |
| Git 基线 | 已建立：`98495dd` |

测试涵盖任务生命周期、来源归属、证据与反馈、研究失败契约、案例生命周期、版本历史、跨任务关联、案例 API、报告引用和扩展能力注册。

### 已知问题与技术风险

- SQLite 仅适合本地单用户验证；不适合并发、多租户或企业审计。
- API 仍在 v0.x 演进，首个稳定公开 API 将采用 `/v1`。
- 外部研究提供器尚未接入，因此不能自动抓取或独立核验网络资料。
- 测试环境出现一条 FastAPI/Starlette 测试客户端的上游弃用提示，暂不影响功能；升级依赖时应复核。
- 个人画像、推荐、积分、社区和企业模块仍缺少完整隐私、滥用与权限模型，现阶段不得上线。

## 9. 开源准备状态

项目的协作骨架已准备好，但在公开发布前，项目所有者仍需明确：

- 开源许可证；
- 维护者与治理模型；
- 私密安全报告渠道与响应时限；
- 隐私政策、数据保留与第三方资料使用规则；
- 商标使用规范、发布密钥与供应链流程。

在这些事项落实前，项目不应声称已采用任何特定开源许可证。
