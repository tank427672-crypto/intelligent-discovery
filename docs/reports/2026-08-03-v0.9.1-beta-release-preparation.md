# v0.9.1 Beta Release Preparation + Case Showcase Foundation 阶段工程报告

日期：2026-08-03  
报告对象：项目架构负责人  
结论：**已完成 Private Beta 前的工程准备基线；尚未获准进入 Public Beta。**

## 1. 当前状态

工程现在可让受邀测试者浏览明确标注为候选的案例种子、建立本地 Beta 用户记录并提交可治理的反馈。系统维持证据优先：候选案例不是已验证 `CaseRecord`，不会获得虚假的可信等级或证据数量。

## 2. 本阶段完成内容

- 建立 `case_seed/`：20 条跨 AI 与科技、开源生态、商业生态、创业与失败案例、社区生态的候选记录。
- 建立前端无关的案例卡片与详情展示契约；详情强制包含证据链、图谱关系、限制和反馈入口。
- 新增 BetaUser（Observer、Tester、Contributor、Reviewer）、BetaFeedback（Experience、Knowledge、Case、Bug、FeatureRequest）及权限检查。
- 新增 Beta 反馈存储、普通治理评审/高优先级缺陷事件分诊、ReleaseCandidate、ReleaseChecklist 和人工批准门禁。
- 新增 CaseLicense、贡献分数预览和仅供未来接入的 AbuseDetectionProvider 契约。
- `CaseViewed`、`SearchPerformed`、`FeedbackSubmitted` 已接入隐私最小化事件记录；事件不记录搜索词或反馈正文。

## 3. 项目结构变化

- `case_seed/cases.json` 与 `case_seed/README.md`：候选种子及导入边界。
- `intelligent_discovery/case_seed.py`：种子加载与公共来源/许可证字段验证。
- `intelligent_discovery/case_view.py`：稳定展示契约。
- `intelligent_discovery/beta.py`：Beta 领域模型、端口、服务及可替换 SQLite 适配器。
- API 新增 `/beta/featured-discoveries`、`/beta/users`、`/beta/feedback`。
- 新增 [Beta 说明](../../BETA.md)、[案例指南](../../CASE_GUIDE.md)、[社区边界](../../COMMUNITY.md)、[发布计划](../../RELEASE_PLAN.md)。

## 4. 案例种子库与版权处理

种子库数量为 20，每条含名称、类型、分类、公开来源 URL、许可证/条款声明与原创结构化摘要。未复制来源正文。许可证声明是工程数据字段，不是法律结论；实际导入前仍须由审核者确认来源可访问、具体使用权限、引用要求、证据定位和案例结论。

## 5. 用户体验与反馈体系

测试用户可先查看 Featured Discoveries，再创建本地 Beta 用户并提交反馈。普通反馈进入周期治理评审，高或严重优先级的 Bug 进入事件分诊；这只是路由建议，不会自动创建事故、修改知识、变更权限或创建进化实验。未来贡献、讨论和求助仍是预留接口，未向用户开放。

## 6. 发布治理

发布路径定义为 Internal Alpha → Private Beta → Public Beta。ReleaseChecklist 覆盖功能、安全、隐私、版权、治理和恢复；所有检查通过之外，仍需人工 `approved`。工程没有自动发布能力，符合人始终在环原则。

## 7. 架构一致性检查

通过。Beta 领域服务依赖 `BetaStore` 和 `EventEmitter` 协议；SQLite 仅为本地适配器。领域模块没有依赖 FastAPI、SQLite、模型 SDK 或外部网络。HTTP 只在 `api.py` 组装服务。案例种子加载也不会绕过既有 Source → Evidence → Finding → CaseRecord 链。

## 9. 风险与设计偏差检查

- **案例真实性风险：高。** 种子是研究候选，而不是逐条验证的案例资产；不得用于确定性结论或推荐。
- **版权风险：中。** 目前只有许可证/条款声明字段，尚未完成逐源法律审核。
- **身份与权限风险：中。** BetaUser 是本地基础模型，不是生产认证/授权系统。
- **数据持久化风险：中。** Beta 反馈使用单机 SQLite；不适合多用户并发、备份、删除服务等级或审计留存。
- **可观测性覆盖风险：低到中。** 已覆盖当前展示、搜索、反馈入口；贡献创建和错误事件需在这些功能真正实现后接入，不能伪造事件。
- **设计偏差：无已知核心领域依赖反转违规。** 但当前 API 仍是开发级组合根，不应直接当作生产部署配置。

## 10. 正式 Beta 建议与下一阶段计划

先进行 Internal Alpha：逐条复核首批高价值案例的来源、许可证和证据链；邀请少量受控测试者；执行数据删除/导出和异常恢复演练。只有清单、人工审核和隐私政策均到位后，才申请 Private Beta。Public Beta 不建议在本阶段后直接开启。

建议下一阶段为 **v0.9.2 Private Beta Operations**：真实身份认证的选型与威胁建模、案例审核工作台、数据权利操作执行、Beta 指标看板、备份/恢复演练，以及基于人工批准的反馈处置追踪。

## 11. 需要架构负责人决策的问题

1. 确认 Private Beta 的测试范围、最大测试人数和可接受的案例候选比例。
2. 确认案例来源许可审核的责任人及“可引用/可总结/不可使用”的标准。
3. 确认测试数据保留期、导出/删除服务承诺及安全事件私密报告渠道。
4. 选择 v0.9.2 的生产身份方案和长期数据库迁移目标。
