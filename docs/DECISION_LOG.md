# 决策记录

此文件是轻量 ADR 索引。每项架构性取舍需记录日期、决定、原因、影响与后续复核条件。

## 2026-08-03 — 架构先行，能力分期入驻

决定：一次性定义完整生态的模块边界与扩展协议，仅实现 v0.1 发现闭环。

原因：避免后续功能（机会雷达、推荐、个人智能、社区）进入时重构核心数据模型；同时不为未验证需求提前实现复杂功能。

## 2026-08-03 — 证据优先

决定：所有发现显式关联来源、置信度和未知项。

原因：智能发现应辅助理解和决策，不能以不可追溯的自动结论替代用户判断。

## 2026-08-03 — 核心服务依赖端口，不依赖 SQLite

决定：`DiscoveryService` 依赖 `DiscoveryRepository` 协议；SQLite 只是当前实现。

原因：便于未来引入关系库、事件存储、知识图谱或远程服务，而不改变任务生命周期规则。

影响：基础设施可替换；新的存储实现必须满足端口契约并通过共同测试。

## 2026-08-03 — 未来生态模块采用能力契约

决定：机会发现、决策分析、个人智能、推荐、案例、社区、贡献、企业与未知模块全部由 `Capability` 和 `Protocol` 表示，初期不实现业务功能。

原因：先稳定边界，再按需求验证能力，避免核心被未来设想耦合。

影响：新模块需走扩展注册和 ADR；插件失败不得破坏发现核心。

## 2026-08-03 — Evidence 成为独立领域对象

决定：将来源与具体证据分开；`Finding` 新增 `evidence_ids`，人工反馈以独立对象保存。

原因：一个来源可能包含支持、反驳和上下文不同的多个片段。仅引用 URL 不足以解释“为什么相信”，也不能承载人工复核结果。

影响：v0.1 的 `source_ids` 暂时兼容；新研究能力应优先创建可定位 Evidence。数据迁移采用 SQLite 追加列，不删除既有记录。

## 2026-08-03 — 研究失败必须是数据，不是静默异常

决定：研究提供器使用结构化失败结果表达不可访问、数据不足、冲突、验证失败与许可限制。

原因：不确定性是智能发现的核心输出之一。静默失败或自动补全都会误导用户并损害证据链。

影响：未来提供器必须实现失败语义、可重试标记和可观测性；不得将失败转换为看似可信的结论。
