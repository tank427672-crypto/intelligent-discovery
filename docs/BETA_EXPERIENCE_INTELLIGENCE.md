# Beta Experience Intelligence

v0.9.3 用于 Private Beta 日常运行准备，而不是用户行为监控或自动化决策。它建立可追溯闭环：

`使用（经同意的元数据）→ 主动反馈/结构化沟通 → BetaInsight → ImprovementProposal → EvolutionCandidate → Experiment → 人工批准 → 发布 → 用户再次验证`

## 数据边界

`ExperienceSignal` 必须得到明确同意，只允许功能、动作、结果、性能桶、错误类型和状态等最小元数据。它拒绝 `content`、`body`、`message`、`query`、`private_text` 等字段，不复制私人知识、搜索内容或沟通正文。用户的导出、删除和审计权继续使用 Data Protection Center。

## 优先级与响应

- **P0**：安全、隐私、数据权利或极高严重度；快速人工响应。
- **P1**：重大功能/稳定性问题；进入事件处理与负责人评估。
- **P2**：反复出现的功能或沟通阻碍；进入周期优化。
- **P3**：一般建议；进入 Beta Review Cycle。

分类仅作分诊建议，不能自动修改代码、知识、权限或规则。

## 共建与专家机制

Beta 用户可提交体验、案例建议和改进意见，但这些都是结构化沟通和待审核请求。专家主要提供证据补充、背景、适用边界和质量增强；用户评价维度是帮助质量、解释能力、沟通效果和长期价值。贡献价值、社区、专业和审核信誉分开记录，不能产生自动特权、积分或排名。

## Beta Review Cycle

每周复盘体验趋势、系统健康、知识质量、沟通效率和安全事件；每月检查改进提案与实验结果；每季度进行架构评审。每次周期输出 Beta Review Report，保留信号范围、分析、人工结论、实验及未解决风险。
